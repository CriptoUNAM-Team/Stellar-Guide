El motor: consenso SCP

Sin minería. Sin apostar. Solo confianza.

En Bitcoin ganas el derecho a escribir quemando energía. En Stellar, cada nodo elige en quién confía (su quorum slice) y la red converge en acuerdo en segundos.

Anatomía de la red

Seis piezas y ya hablas Stellar

Cuenta

Par de llaves. Pública G… = tu IBAN. Secreta S… = tu firma. Nunca la compartas.

Asset

El nativo es XLM. O cualquier token emitido: USDC, un peso, un bono.

Ledger

El estado global. Se cierra cada ~5 s. La “foto” compartida de todos los saldos.

Operación

La acción: pagar, crear cuenta, cambiar activo. La unidad mínima.

Transacción

Una o varias operaciones, firmadas con tu llave secreta y enviadas a la red.

Testnet

Red de pruebas con dinero falso e ilimitado. Aquí practicas todo gratis.

Smart contracts

Soroban: lógica programable en Rust

  • Escribes en Rust — seguridad de memoria y velocidad, ideal para manejar dinero.
  • Compila a WASM — un binario que la red ejecuta igual en todos los nodos.
  • Estado on-chain — el contrato guarda datos (saldos, lotes, empleados) en el ledger.
  • SDK + CLI oficiales — herramientas para compilar, desplegar y probar sin fricción.

Contrato vivo on-chain
Tu primer contrato · explicado

Así se declara un contrato

// contracts/counter/src/lib.rs
#![no_std]                       // 1 · sin std: binarios chicos para la red
use soroban_sdk::{contract, contractimpl, Env, symbol_short, Symbol};

#[contract]                       // 2 · esta struct ES el contrato
pub struct Counter;

#[contractimpl]                   // 3 · expone los métodos como funciones públicas
impl Counter {
    pub fn increment(env: Env) -> u32 {     // 4 · env = acceso al ledger
        let key: Symbol = symbol_short!("COUNT");  // 5 · la “casilla” del dato
        let mut n: u32 = env.storage().instance()
            .get(&key).unwrap_or(0);             // 6 · LEE (0 si no existe)
        n += 1;                                    // 7 · tu regla de negocio
        env.storage().instance().set(&key, &n);     // 8 · ESCRIBE en el ledger
        n                                            // 9 · DEVUELVE el resultado
    }
}
  • 1 · #![no_std] — la red corre binarios mínimos, sin la librería estándar.
  • 2 · #[contract] — marca la struct como el contrato en sí.
  • 3 · #[contractimpl] — cada pub fn aquí se vuelve invocable on-chain.
  • 4 · Env — tu puerta al ledger: almacenamiento, tiempo y eventos.
  • 6→8 · storage — es la base de datos del contrato: get para leer, set para guardar.

Todo contrato sigue el mismo patrón: leer estado → aplicar reglas → guardar estado → responder.

Caso real · industria de la transformación

Trazabilidad de manufactura, on-chain

// Lote de producción registrado en el ledger
#[contracttype]                  // dato que vive on-chain
pub struct Batch {
    pub id: u64,            // folio único del lote
    pub producer: Address,  // quién lo fabricó
    pub product: Symbol,    // qué producto es
    pub quantity: u32,      // unidades producidas
    pub created_at: u64,    // sello de tiempo del ledger
    pub quality_ok: bool,   // ¿pasó control de calidad?
    pub certifier: Address, // quién firmó la certificación
}
  • Cada lote queda registrado con folio, origen y fecha — imposible de alterar después.
  • Calidad firma on-chain: el certificado no se puede falsificar ni “editar”.
  • El cliente o la aduana verifican origen y calidad con solo el folio.
  • El pago al proveedor puede liberarse solo cuando el lote pasa calidad.

Misma estructura que el contador — solo cambian los datos y las reglas. En el repo hay además contratos de nómina, ahorro, préstamos, yield y certificados NFT.

Manos a la obra

De 0 a corriendo en 5 pasos

0
brew install stellar-cli

Instala la CLI oficial (en Linux/Windows usa el instalador de su web). Verifica con stellar --version.

1
stellar keys generate alice --network testnet --fund

Crea una identidad llamada alice en la red de pruebas y le deposita XLM falso gratis. Cambia alice por el nombre que quieras.

2
stellar contract build

Córrelo dentro de la carpeta del contrato. Compila tu Rust a WASM en target/wasm32.../.

3
stellar contract deploy --wasm ruta/al/contrato.wasm --source alice --network testnet

Sube el contrato a la red. Devuelve un ID que empieza con C…: cópialo, lo usas en el paso 4.

4
stellar contract invoke --id C… --source alice --network testnet -- increment

Llama a una función del contrato. Reemplaza C… por el ID del paso 3; lo que va después de -- es el método. La salida es el valor devuelto.
